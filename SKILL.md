# Go Live — від папки на комп'ютері до живого сайту

Мета: людина без технічного досвіду отримує робоче посилання `https://<назва>.vercel.app`
(або свій домен) і далі оновлює сайт однією фразою в чаті.

Два режими публікації — людина обирає на першому запуску (крок 1). Нижче у файлі вони звуться
коротко «Сейф» і «Просто»; людині кажи «через GitHub» і «напряму у Vercel».

| Режим | Людині | Схема | Як оновлюється |
| --- | --- | --- | --- |
| **Сейф** (основний) | «через GitHub» | папка → приватний репозиторій GitHub → Vercel (Git-інтеграція) | `git push` у `main`, Vercel публікує сам |
| **Просто** | «напряму у Vercel» | папка → Vercel | агент виконує `vercel deploy --prod` |

Режими не змішуй. Проєкт, підключений до GitHub, публікується **лише через push**: `vercel deploy`
там не запускай ніколи, навіть «один раз» — інакше сайт оновиться сьогодні, а наступні зміни
мовчки не публікуватимуться. GitHub Actions для деплою не використовуються в жодному режимі.

## Де ти працюєш

Людина найчастіше пише з **застосунку Claude** (вкладка Code, локальна сесія) або з **застосунку
ChatGPT** (Codex). Що таке термінал, вона, найімовірніше, не знає.

- Усі команди виконуй сам. Не проси людину нічого вводити в термінал, якщо є інший шлях.
- **Перед кожною командою, на яку застосунок попросить дозволу, одним реченням скажи, що зараз
  буде і що натиснути**: «Зараз застосунок спитає дозволу встановити потрібну програму — натисніть Allow»
  (у Claude: Allow once / Always allow; у ChatGPT: «Так» / «Yes»). У Codex мережа в пісочниці за
  замовчуванням вимкнена: кожна команда з інтернетом (`npm`, `npx`, `curl`, `git push`, `gh`,
  `vercel`) проситиме дозволу — попереджай про це.
- Команди, які чекають дії людини в браузері (`vercel login`, `gh auth login`), запускай **у фоні**
  або з тайм-аутом 10 хвилин і не блокуй розмову.
- ОС: `uname -s` (Darwin — macOS, Linux) або Windows. На Windows без bash виконуй еквіваленти
  в PowerShell (`curl.exe`, `Expand-Archive`, `Start-Process <url>`).
- `sudo` не запускай ніколи: пароль адміністратора людина вводить лише в системному вікні.
- Технічні подробиці (назви програм, команди) людині не переказуй, якщо вона не питає. Досить
  «встановлюю потрібні програми, це один раз».
- Не клади команду в змінну (`$VC deploy`): у zsh на macOS така змінна не розбивається на слова.
  Пиши команду повністю.

У Claude Code в терміналі можна просто попросити людину ввести `! <команда>` у полі чату.

## Правила спілкування

- Говори мовою людини, простими словами, без жаргону. Кожен термін пояснюй одним реченням
  («репозиторій — це папка проєкту в хмарі GitHub з історією всіх змін»).
- Вибір (режим, назва, favicon, прев'ю) пропонуй **інструментом запитань із варіантами**
  (`AskUserQuestion` у Claude: 2–4 варіанти, «Інше» додається саме). Немає такого інструмента —
  нумерований список і прохання відповісти цифрою.
- Вхід в акаунти людина робить **сама, у браузері**. Паролі, коди 2FA і токени ніколи не проси
  й не вводь за неї.
- Нічого не публікуй у відкритий GitHub: репозиторій завжди `--private`.

## Крок 0. Де ми і що робимо

1. Корінь проєкту = поточна папка. **Якщо це домашня папка (`~`, `$HOME`, `C:\Users\<ім'я>`) або
   системна — зупинись** і попроси відкрити саме папку з сайтом. `git init` у домашній папці
   заборонений.
2. Визнач режим роботи:
   - Є `.vercel/project.json` **і** `git remote get-url origin` вказує на GitHub → **«Оновлення» в
     режимі «Сейф»**.
   - Є `.vercel/project.json`, а origin немає → **«Оновлення» в режимі «Просто»**.
   - Просять іншу адресу → **«Зміна адреси»**. Просять GitHub («підключи GitHub», «додай сейф»)
     для сайту, опублікованого напряму, → **«Додати сейф»**. Просять свій домен → **«Власний домен»** (`references/domain.md`);
     якщо сайт ще не опублікований — спершу перша публікація.
   - Інакше → **перша публікація**, кроки 1–8.

## Крок 1. Як публікуємо (обов'язкове запитання)

Спершу тихо перевір, що вже є, і нічого не встановлюй:

```bash
node --version
vercel --version 2>/dev/null || echo "vercel: немає"
# macOS: спершу xcode-select -p — інакше git --version відкриє вікно встановлення
xcode-select -p >/dev/null 2>&1 && git --version
gh auth status 2>&1 || ~/.local/bin/gh auth status 2>&1
```

Потім **запитай людину завжди**, навіть якщо все вже встановлено:

- **«Через GitHub (рекомендовано)»** — копія проєкту й історія всіх змін у приватному сховищі
  GitHub (наш «сейф»); Vercel оновлює сайт сам після кожного збереження в сейф. Потрібні акаунти GitHub
  і Vercel.
- **«Напряму у Vercel»** — лише акаунт Vercel, найменше кроків. Без копії й історії змін у GitHub.

Першим і з позначкою «рекомендовано» завжди став «Через GitHub». Скажи, що GitHub можна додати й
пізніше фразою «підключи GitHub».

## Крок 2. Програми на комп'ютері

| Режим | Що потрібно |
| --- | --- |
| Просто | Node.js (для програми Vercel) |
| Сейф | Node.js, Git, GitHub CLI (`gh`) |

Чогось бракує → **запропонуй встановити це сам** і поясни людині, що побачить (вікно установника,
запит дозволу). Як ставити без терміналу і без `sudo` на macOS і Windows — у
**`references/install.md`**. Після встановлення перевір ще раз.

**Програма Vercel (Vercel CLI):** `vercel --version` працює → пиши `vercel …`. Ні → після Node
`npm i -g vercel` (Node, встановлений за `references/install.md` у `~/.local/node`, ставить її без
пароля). Помилка прав доступу (`EACCES`) → не чіпай `sudo`, пиши в усіх командах
`npx --yes vercel@latest …` (далі в цьому файлі — просто `vercel`).
Стара версія (`vercel --version` нижче 60: немає `vercel project create`, команди відповідають підказками)
→ онови `npm i -g vercel@latest` або пиши `npx --yes vercel@latest …`.

## Крок 3. Акаунти і вхід (без терміналу)

**Vercel.**
1. Немає акаунта → https://vercel.com/signup. Кнопки: Continue with Google, GitHub, ChatGPT,
   Apple або Email. У режимі «Сейф» найпростіше — **Continue with GitHub**: тоді Vercel і GitHub
   одразу пов'язані. Тариф — **Hobby** (особисті проєкти, безкоштовно).
2. Вхід програми: `vercel whoami`. Не увійшли → запусти `vercel login` **у фоні**. Програма
   виведе посилання `https://vercel.com/oauth/device?user_code=XXXX-XXXX` і сама відкриє браузер.
   Скажи людині: «У браузері відкрилась сторінка Vercel. Перевірте, що код там XXXX-XXXX, і
   підтвердьте». Браузер не відкрився → відкрий посилання сам (`open <url>` / `Start-Process <url>`).
   Код діє 10 хвилин. Дочекайся завершення, перевір `vercel whoami`.

**GitHub (лише режим «Сейф»).**
1. Немає акаунта → https://github.com/signup. Найшвидше — **Continue with Google** (або Apple):
   окремий пароль не потрібен. Username — коротко, латиницею: він буде в адресах репозиторіїв.
2. Вхід: `gh auth status`. Не увійшли → запусти **у фоні**
   `gh auth login --hostname github.com --git-protocol https --web`. Без терміналу він виведе
   «First copy your one-time code: XXXX-XXXX» і посилання https://github.com/login/device, але
   браузер **не відкриє** — відкрий сам і скажи код. Людина вводить код → Continue → Authorize.
   Код діє 15 хвилин.
3. Після входу обов'язково `gh auth setup-git` — без цього `git push` не спрацює.

Фоновий запуск неможливий → попроси людину відкрити вбудований термінал застосунку (Claude:
кнопка **Terminal** у шапці сесії або Ctrl+\`; ChatGPT: Ctrl+\`) і ввести там `gh auth login`.

## Крок 4. Перевірка проєкту перед публікацією

1. **Що це за проєкт:**
   - `index.html` у корені → статичний сайт, збирати нічого не треба.
   - HTML-файл з іншою назвою і немає `index.html` → **перейменуй його в `index.html`** (інакше
     сайт відкриється з помилкою 404) і скажи людині, що зробив і навіщо. Кілька HTML-файлів і
     жодного `index.html` → запитай, який головний.
   - Джерело, а не сайт: `.pptx`, `.pdf`, `.docx`, папка з текстом → людина хоче **сайт із цього
     матеріалу**. Витягни текст (`soffice --headless --convert-to pdf`, далі `pdftotext -layout`) і
     **напиши справжню сторінку**: заголовки, секції, списки, адаптив під телефон. Вихідний файл
     можна покласти поруч як «Завантажити PDF». Сторінку зі скриншотів слайдів не роби.
   - `package.json` → фреймворк (Vite, Next.js, Astro…). Vercel визначить його сам; якщо є Node,
     переконайся, що `npm run build` проходить.
2. **Що стане публічним.** Усе, що піде на Vercel, відкривається за посиланням. Подивись, що лежить
   у папці, і якщо там є щось, крім сайту (документи, особисті фото, архіви), — **покажи людині
   список і запитай**, що прибрати. Зайве додай у `.vercelignore` («Просто») або `.gitignore`
   («Сейф»).
3. **Секрети:**
   ```bash
   grep -rInE "(sk-[A-Za-z0-9_-]{20,}|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{30,}|api[_-]?key|secret|password)\s*[:=]" \
     --exclude-dir={node_modules,.git,dist,.next} . | head -20
   ```
   І файли `.env*`, `*.pem`, `*.key`, `credentials*.json`, `service-account*.json`. Ключ у файлі, який
   піде в браузер → **зупинись і поясни**: його побачить кожен відвідувач. Ключі — у Vercel →
   Settings → Environment Variables і лише в серверному коді.
4. **Файл винятків** — створи або доповни (`.vercelignore` у «Просто», `.gitignore` у «Сейф»):
   ```
   .DS_Store
   Thumbs.db
   node_modules/
   .vercel
   .env*
   !.env.example
   *.pem
   *.key
   .claude/
   .agents/
   ```
   Службові папки агента (`.claude/`, `.agents/`) в інтернет не потрапляють.
5. Відео або архіви понад 50 МБ не публікуй — запропонуй стиснути або винести на YouTube.

## Крок 5. Назва = адреса сайту (обов'язкове підтвердження)

Назва однакова для проєкту Vercel, адреси `https://<назва>.vercel.app` і (у «Сейф») репозиторію.

1. **Базова назва** — з назви папки: латиниця (транслітеруй кирилицю: «Мій Сайт Йога» →
   `miy-sayt-yoga`), малі літери, пробіли і `_` → `-`, лише `a-z 0-9 -`, до 50 символів.
2. **Кандидати** (6–8): базова назва; коротша версія; змістовні варіанти з вмісту сайту
   (ім'я/бренд + `-site`, `-online`, тема + місто тощо); базова + `-2`, `-3`.
3. **Перевір усі разом** (скрипт поруч із цим файлом; `--no-github` у режимі «Просто»):
   ```bash
   bash "<шлях-до-скіла>/scripts/check-name.sh" [--no-github] name1 name2 name3 ...
   ```
   `free` — вільна; `taken` — зайнята (причина в третій колонці); `unknown` — перевір ще раз.
   Без bash (Windows/PowerShell) перевір кожну назву вручну: `curl.exe -sI https://<назва>.vercel.app`
   — вільна, якщо у відповіді є `x-vercel-error: DEPLOYMENT_NOT_FOUND`; плюс `vercel project inspect
   <назва>` (знайшовся — зайнята у вас) і в «Сейф» `gh repo view <login>/<назва>`.
4. **Запитай людину завжди**, навіть якщо базова назва вільна. Варіанти — лише `free`, до 4 штук,
   першим — базова назва, якщо вільна (з позначкою «рекомендовано»); в описі кожного — повна адреса.
   Базова назва зайнята → прямо скажи це і чому.
5. Людина вписала свою назву → нормалізуй, перевір тим самим способом.

## Крок 6. Favicon і прев'ю посилання в месенджерах

Мета: у Telegram, WhatsApp, Viber, Facebook посилання показує заголовок, опис і картинку, а у
вкладці браузера — іконку.

1. **Favicon** — запитай із варіантами:
   - «У мене є картинка» → людина дає шлях; скопіюй у корінь як `favicon.png` (або `.ico/.svg/.jpg`).
     Квадратна, від 64×64; для iPhone додатково `apple-touch-icon.png` 180×180, якщо є PNG.
   - «Згенерувати з емодзі» → запропонуй 3 емодзі за темою, створи `favicon.svg`:
     `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100"><text y=".9em" font-size="90">🌿</text></svg>`
   - «Згенерувати з літери» → `favicon.svg` з першою літерою бренду на кольоровому квадраті.
   - «Пропустити».
2. **Заголовок і опис** — склади з вмісту сторінки 2 варіанти (title до 60 символів,
   description до 160), запитай із варіантами. Мова — мова сайту.
3. **Картинка прев'ю** (1200×630) — запитай із варіантами:
   - «Скріншот першого екрана сайту» → якщо є Chrome:
     ```bash
     # macOS: CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
     # Windows: "C:\Program Files\Google\Chrome\Application\chrome.exe"
     "$CHROME" --headless=new --hide-scrollbars --window-size=1200,630 \
       --screenshot="$PWD/og-image.png" "file://$PWD/index.html"
     # macOS: стиснути в JPEG (WhatsApp не показує важкі картинки; ціль до 300 КБ)
     sips -s format jpeg -s formatOptions 80 og-image.png --out og-image.jpg && rm og-image.png
     ```
     Покажи результат людині, перш ніж іти далі.
   - «У мене є картинка» → скопіюй як `og-image.jpg`/`.png`; попередь, якщо не 1.91:1 або > 1 МБ.
   - «Без картинки».
4. **Теги** — у `<head>` `index.html` одразу після `<meta charset…>` (Next.js — `metadata` в
   `app/layout`, Vite — кореневий `index.html`). Однойменні теги **замінюй**, не дублюй. Адреси
   картинок — **лише абсолютні** (відносні месенджери ігнорують):
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1">
   <title>ЗАГОЛОВОК</title>
   <meta name="description" content="ОПИС">
   <link rel="icon" href="/favicon.svg" type="image/svg+xml">
   <link rel="apple-touch-icon" href="/apple-touch-icon.png">
   <link rel="canonical" href="https://НАЗВА.vercel.app/">
   <meta property="og:type" content="website">
   <meta property="og:url" content="https://НАЗВА.vercel.app/">
   <meta property="og:title" content="ЗАГОЛОВОК">
   <meta property="og:description" content="ОПИС">
   <meta property="og:image" content="https://НАЗВА.vercel.app/og-image.jpg">
   <meta property="og:image:width" content="1200">
   <meta property="og:image:height" content="630">
   <meta name="twitter:card" content="summary_large_image">
   ```
   Рядки для відсутніх файлів не додавай. `viewport` — лише якщо його немає.

## Крок 7А. Публікація — режим «Просто»

```bash
vercel project create НАЗВА          # створює проєкт на Vercel
vercel link --yes --project НАЗВА    # прив'язує папку до проєкту (.vercel/project.json)
vercel deploy --prod --yes           # публікує; у відповіді — адреса
```

- Кілька команд (team) у Vercel і `link` просить scope → запитай, яку взяти, і додавай `--scope <team>`.
- У папці вже є git з `origin` на GitHub → `vercel link` сам підключить репозиторій. Тоді
  запропонуй режим «Сейф», а не «Просто».

## Крок 7Б. Публікація — режим «Сейф»

```bash
git init -b main 2>/dev/null || { git init && git checkout -b main; }
# пошта автора — від акаунта GitHub, інакше Vercel мовчки не запустить публікацію
git config user.name "$(gh api user -q .login)"
git config user.email "$(gh api user -q .id)+$(gh api user -q .login)@users.noreply.github.com"
git add <конкретні файли й папки сайту>       # не «git add .» наосліп — спершу git status
git status                                     # немає .env, ключів, node_modules
git commit -m "Перша публікація сайту"
gh repo create НАЗВА --private --source=. --remote=origin   # без push: його зробимо після Vercel
vercel project create НАЗВА                    # створює проєкт на Vercel
vercel link --yes --project НАЗВА              # прив'язує папку і підключає репозиторій
vercel git connect --yes                       # явна перевірка зв'язку; має сказати «Connected»
git push -u origin main                        # цей push запускає першу публікацію
```

Помилки `vercel git connect`:
- **«Add a Login Connection»** — акаунт Vercel створено через Google або пошту, GitHub до нього
  не прив'язаний. Відкрий людині Vercel → аватар → **Account Settings → Authentication** → GitHub
  → Connect. Повтори `vercel git connect --yes`.
- **«Install GitHub App»** або немає доступу до репозиторію → відкрий
  https://github.com/apps/vercel/installations/new → обрати акаунт → **All repositories** →
  Install. Повтори.
- **«already linked to another Vercel account»** — GitHub прив'язаний до іншого акаунта Vercel
  (людина колись входила через інший Google). Відв'язати там: Settings → Authentication.

**Не обходь ці помилки командою `vercel deploy`.** Push у `main` уже зроблено, а публікації немає
(так буває, якщо Vercel підключили після push) → `git commit --allow-empty -m "Публікація на Vercel"`
і `git push`.

## Крок 8. Перевірка (не звітуй про успіх без неї)

```bash
# чекати до ~3 хвилин, поки сайт відповість 200 (у фоні, не блокуй розмову)
for i in $(seq 1 36); do
  code=$(curl -s -o /dev/null -w "%{http_code}" https://НАЗВА.vercel.app/)
  [ "$code" = 200 ] && break; sleep 5
done; echo "site: $code"
curl -s -o /dev/null -w "favicon: %{http_code}\n" https://НАЗВА.vercel.app/favicon.svg
curl -s -o /dev/null -w "og-image: %{http_code}\n" https://НАЗВА.vercel.app/og-image.jpg
curl -s https://НАЗВА.vercel.app/ | grep -E 'og:(title|image)'
```

- «Сейф»: 2–3 хвилини `404`, а `vercel ls НАЗВА` без публікацій → не спрацював зв'язок із GitHub;
  повернись до помилок кроку 7Б.
- `401` замість `200` → увімкнено захист публікацій: `vercel project protection disable НАЗВА --sso`
  або Vercel → Project → Settings → Deployment Protection → Vercel Authentication: Disabled.
- Адреса відрізняється від `НАЗВА.vercel.app` → знайди реальну (`vercel project inspect НАЗВА`),
  **онови абсолютні адреси в og-тегах** і опублікуй ще раз.
- Сторінка з картинками «стрибає» під час завантаження → постав `width`/`height` або `aspect-ratio`.

## Що сказати людині наприкінці

1. Посилання на сайт і що воно відкривається.
2. **Як оновлювати:** «змініть файли або попросіть мене змінити — і скажіть "опублікуй зміни"».
   Через хвилину зміни онлайн. Невдалу версію можна повернути: Vercel → Deployments → попередня
   версія → **Instant Rollback**.
3. **Прев'ю:** перевірити посилання — https://www.opengraph.xyz. Telegram пам'ятає старе прев'ю:
   змінили картинку → надіслати посилання боту @WebpageBot.
4. **Чесно про безкоштовність:** Hobby — для особистих і некомерційних проєктів. Сайт, що
   рекламує ваші платні послуги, Vercel вважає комерційним → тариф Pro (20 $/міс).
5. «Просто»: GitHub (копію й історію змін) можна додати будь-коли фразою «підключи GitHub».
6. **Власний домен** — запитай, чи хоче людина адресу на своєму домені. Так → `references/domain.md`.

## Режим «Оновлення»

1. Покажи людині простими словами, що змінилось (`git status` у «Сейф»; у «Просто» — які файли
   змінено після останньої публікації, якщо це видно).
2. Перевір секрети (крок 4.3) у нових файлах.
3. Публікація:
   - «Просто»: `vercel deploy --prod --yes`.
   - «Сейф»: `git add <змінені файли>` → `git commit -m "<що змінено, по-людськи>"` → `git push`.
     **Не `vercel deploy`.**
4. Крок 8 на реальній адресі. Назву, favicon і теги не чіпай, якщо не просили.

## Режим «Додати сейф» (був «Просто» → стає «Сейф»)

1. Поясни, що це дасть (копія й історія змін у приватному GitHub, автопублікація після push) і що
   потрібно (акаунт GitHub, Git, `gh`). Підтвердження → крок 2 і вхід у GitHub з кроку 3.
2. `.vercelignore` → перенеси правила в `.gitignore`. Далі як у кроці 7Б: `git init`, пошта автора,
   commit, `gh repo create НАЗВА --private --source=. --remote=origin`, `vercel git connect --yes`,
   `git push -u origin main`.
3. Крок 8. Скажи, що відтепер сайт оновлюється після кожного збереження в сейф.

## Режим «Зміна адреси»

1. Нова назва — перевір (крок 5) і підтверди запитанням.
2. `vercel project rename СТАРА НОВА`; у «Сейф» ще `gh repo rename НОВА --yes` (remote оновиться сам).
3. Онови абсолютні адреси в тегах (`canonical`, `og:url`, `og:image`) і опублікуй (як в «Оновленні»).
4. Крок 8 на новій адресі. Скажи, що стара адреса більше не працює.

## Чого не робити

- **Сайт із картинок не робити.** Сторінка зі скриншотів слайдів чи сторінок PDF — не сайт: її не
  прочитати з телефона і не знайти в пошуку. Картинками — лише фото, ілюстрації, галерею робіт.
- Не робити репозиторій публічним.
- Не запускати `git init` / `git add` у домашній папці чи поза коренем проєкту.
- Не публікувати `.env`, ключі, `node_modules`, `.vercel`, папки `.claude/` і `.agents/`.
- У режимі «Сейф» не публікувати через `vercel deploy`. Не створювати GitHub Actions для деплою.
- Не запускати `sudo`, не вводити паролі, коди 2FA і токени, не просити їх у чаті.
- Не купувати домени і не вводити платіжні дані за людину. Не чіпати MX, TXT, NS-записи.
- Не повідомляти «готово» без кроку 8.
