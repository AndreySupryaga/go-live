# Режим «Власний домен»

Сайт лишається на Vercel, домен лише вказує на нього. Людина платить тільки за адресу; хостинг
окремо не оплачується і переносити сайт нікуди не треба. Правило Hobby щодо комерційного
використання від домену не змінюється.

## 1. Домен уже є?

Ні → поясни два шляхи і запитай із варіантами:

- **Купити просто у Vercel** — найпростіше: DNS і HTTPS налаштуються самі. https://vercel.com/domains
  (або Vercel → Domains → Buy) → пошук → Buy. `.com` ≈ 11–12 $/рік; ціну дивись на сторінці
  (`vercel domains price <домен>`). Українських `.ua` / `.com.ua` там немає. Деякі зони дешеві лише
  перший рік (`.online`, `.pro`, `.site`) — звертай увагу людини на ціну продовження.
- **В українського реєстратора** (nic.ua, imena.ua, hostiq.ua тощо) — потрібен для `.com.ua`
  (≈ 460–740 грн/рік, торгова марка не потрібна). Потім додати два записи DNS (крок 3).

**Не купуй за людину** і не вводь платіжні дані: це її рішення і гроші. `vercel domains buy` не
запускай. Чекай, поки людина напише, що купила.

## 2. Додати домен до проєкту

```bash
vercel domains add ДОМЕН НАЗВА-ПРОЄКТУ
vercel domains add www.ДОМЕН НАЗВА-ПРОЄКТУ
```

Або Vercel → Project → Settings → Domains → Add. Головний варіант один: `www.ДОМЕН` перенаправляє
на `ДОМЕН` (Settings → Domains → www → Redirect to).

Домен куплено у Vercel → записи не потрібні, переходь до кроку 5.

## 3. Які записи потрібні

`vercel domains inspect ДОМЕН` (і для www) або картка домену у Vercel. **Бери точні значення з
Vercel, не з пам'яті**: IP для `A` буває різним (76.76.21.21 або новіший), а `CNAME` для `www`
тепер свій для кожного проєкту (вигляду `xxxx.vercel-dns-0xx.com`). Типово: `A` для `@` і `CNAME`
для `www`. Записів `AAAA` на Vercel не додавай.

## 4. Внести записи в кабінеті реєстратора — запитай із варіантами

- **«Налаштуй за мене в браузері»** — якщо в тебе є інструменти керування браузером (у Claude:
  Claude in Chrome, `mcp__claude-in-chrome__*`, потрібне розширення і платний план). Порядок:
  1. Спитай, де куплено домен; відкрий сайт реєстратора в **новій вкладці**.
  2. Вхід, 2FA і CAPTCHA людина робить **сама** — зупинись і чекай «увійшов». Паролі й коди не
     вводь і не проси.
  3. Знайди керування DNS цього домену. **Спершу покажи поточні записи і план змін** («додам
     A @ → …, CNAME www → …; видалю A @ → 1.2.3.4 парковки реєстратора») і чекай «так».
  4. Додай або зміни лише `A @` і `CNAME www`. Конфліктні `A`/`AAAA` на `@` і `CNAME`/`A` на `www`
     (зазвичай «парковка» реєстратора) — замінюй лише після підтвердження.
  5. **Ніколи не чіпай** `MX` (пошта), `TXT` (SPF/DKIM, підтвердження Google тощо), `NS`; не
     змінюй nameservers і DNSSEC без прямого прохання.
  6. Збережи, зроби скриншот результату і покажи людині.
- **«Дай інструкцію, зроблю сам»** — таблиця записів (Тип / Ім'я / Значення) і шлях: «кабінет
  реєстратора → Домени → ДОМЕН → DNS / Керування DNS-записами → Додати запис». Те саме
  попередження про MX і TXT.

## 5. Перевірка

DNS зазвичай оновлюється за хвилини, інколи до кількох годин. Перевіряй у фоні:

```bash
vercel domains verify ДОМЕН          # пояснює, що не так, якщо записи ще неправильні
dig +short ДОМЕН A; dig +short www.ДОМЕН CNAME    # Windows: nslookup ДОМЕН
curl -sI https://ДОМЕН | head -1     # 200; сертифікат HTTPS Vercel видає сам
```

Vercel → Settings → Domains показує **Valid Configuration**.

## 6. Оновити теги

`canonical`, `og:url`, `og:image` → `https://ДОМЕН/…`, потім опублікуй так, як заведено в режимі
проєкту («Просто» — `vercel deploy --prod --yes`, «Сейф» — commit і push). Скажи, що адреса
`назва.vercel.app` теж продовжує працювати.
